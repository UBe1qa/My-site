# 공평뽑기 / Pickboard (pick)

뽑기·추첨 웹 도구 7개: 돌림판, 사다리타기, 제비뽑기(여러 명 뽑기·당첨 쪽지·순서 정하기), 팀 나누기, 랜덤 숫자, 동전, 주사위. 정적 사이트(서버 코드 없음, 배포 때 빌드 없음). 명단은 서버로 보내지 않는다(결과 링크를 만들어 남에게 보낼 때만 그 링크 안에 들어간다).
- 주소: https://pick.lumenlab.page (Worker `pick`, workers.dev 끔). 영어 `/` = x-default, 한국어 `/ko/`. 2026-10-09 만듦, 2026-10-10 제3자 평가와 재평가를 반영해 고침.
- **결과를 한쪽으로 기울이는 기능(특정 이름이 나오게 하기, 숨은 가중치, 누구를 어느 팀에 넣기)은 만들지 않는다.** 확률을 바꾸는 방법은 같은 이름을 두 번 넣는 것처럼 화면에 보이는 것뿐.
- 도박처럼 보이면 안 된다(광고 정책): 숫자판·칩 그림, '베팅·배당·잭팟' 같은 말 금지. 한국어 '돌림판·뽑기·추첨', 영어 'wheel·picker·draw'. '룰렛 돌리기'는 돌림판 페이지의 제목·FAQ의 검색어 곁말로만.
- 사실과 다른 말을 쓰지 않는다: 명단 한도는 5,000줄("제한 없음" 금지), 방문 통계는 Cloudflare Web Analytics가 돈다("분석 도구 없음" 금지), '완전한 무작위·진짜 난수' 금지. `_dev/check.py`가 이런 말이 다시 들어오면 실패시킨다.

## 폴더
- `assets/core/` 핵심 로직(화면을 모르는 파일, 노드에서도 돈다)
  - `rng.js` 씨앗(32바이트, `crypto.getRandomValues`) → xoshiro256** → 거절 표본으로 정수(`below`). `Math.random()`과 나머지(%) 치우침 없음.
  - `pick.js` 섞기(Fisher–Yates), 여러 명 뽑기, 쪽지, 팀, 숫자, 동전, 주사위, 돌림판 각도(`wheelPick` → `wheelRotation`, 확인용 `wheelIndexAt`), 한도 `LIMITS`.
    - **명단의 순서에 기대지 않는 뽑기**: `wheelDraw`·`drawSome`·`drawOrder`·`drawSlips`·`drawTeams`. 이름을 코드 포인트 순으로 놓은 '정해진 자리'(`canonicalOrder`)를 기준으로 뽑고 원래 번호로 돌려준다. 자리는 **고른 꼴의 이름**으로 정한다(`seats`가 `cleanName`을 거친다. 화면이 이미 고른 이름을 주지만 한 번 더 막는다). `legacy = true`면 옛 링크(형식 1)처럼 넣은 순서를 자리로 쓴다.
    - 그리기 계산: `sliceColorCount`·`labelFlipped`·`labelSize`, 좁은 칸에 이름 맞추기 `fitLabel`·`commonPrefixLength`(앞이 같은 명단은 뒤쪽을 살린다).
  - `ladder.js` 사다리 만들기·길 따라가기·한 판(`playLadder`: **아래 칸을 먼저 섞고** 사다리를 만든다).
  - `name.js` **이름 고르기와 확인 코드.** `cleanName`(이름을 한 가지 꼴로: 제어 문자·빈칸처럼 보이는 글자 → 공백, 보이지 않는 글자 지우기, 그림 글자 안의 U+200D·U+FE0F·깃발 꼬리표만 남기기, NFC, 공백 정리), `plainName`(옛 다듬기: 공백만), `hadHidden`, `compareCodePoints`, `sha256Hex`(직접 짠 SHA-256), `listCode`·`ladderCode`(확인 코드 8자리). 지우는 글자의 범위는 숫자로 적혀 있다(브라우저의 유니코드 판에 기대지 않게. 로직 테스트가 노드의 유니코드 표와 전수 대조).
  - `share.js` 명단 읽기(`parseList`: 한 줄이면 쉼표·탭으로 나눔, 이름마다 `cleanName`, `tabs` = 여러 칸 붙여 넣기 표시, `hidden` = 보이지 않는 글자를 지운 줄 수), 칸 고르기(`columns`·`pickColumn`), 기록에 명단이 남았는지(`historyHolds`), 공유 링크 넣고 빼기(`#r=2.<도구>.<씨앗 43자>.<base64url JSON>`, 길이 한도 `MAX_HASH` 40만 자, `shareLength`). `decodeShare`는 고른 꼴이 아닌 이름을 고쳐 읽고 `cleaned: true`를 돌려준다. `encodeShare`는 고른 꼴의 이름으로만 만든다.
  - `input.js` 사람이 친 정수 읽기(`readInteger`: 전각 숫자·자릿수 쉼표·여러 빼기표, 15자리까지).
- `assets/app.js` 공통 화면 코드(명단 칸: 저장·잠금·지우기와 되돌리기·링크의 명단 가져오기·칸 고르기·확인 코드, 공유 링크와 표시 종류, 열 수 없는 링크 알림, 큰 결과 이름 맞추기 `fitName`, 최근 결과, 소리, 다른 언어 안내 띠, 루멘랩 칸, 전체 화면, 색종이). `assets/tools/<도구>.js` 도구별 화면. 화면 글자는 페이지 안 `<script id="i18n">`에서 읽는다(코드에 글자를 적지 않는다).
- `assets/style.css` 색 이름은 `:root`에. 강조색은 바늘 빨강 `--pick` 하나(뽑는 행동과 뽑힌 것), 여러 색 `--s1`~`--s8`은 돌림판·팀 표시 안에서만.
- `assets/fonts/` 화면 글자만 담은 조각 글꼴 `pk-en-<지문>.woff2`·`pk-ko-<지문>.woff2`(= `_dev/font.py`가 만든 것)와 라이선스 전문 `OFL.txt`. `_headers`가 이 폴더를 1년 저장하게 한다(이름에 지문이 있어 바뀌면 이름도 바뀐다).
- `assets/ads-config.js` 애드센스: client 있음(자동 광고 코드는 도구·글 `<head>`), 수동 자리 번호 `slots`는 비어 있음. 자리 2곳(mid = 도구 설명 글 다음, bottom = 가이드 목록 다음). localhost나 `?adpreview`면 빗금 상자로만 보인다.

  - `_dev/content.json` 화면 글자(`ui`·`toolUi`), 화면 코드가 쓰는 글자(`js`), 도구별 제목·설명·본문·FAQ(`tools`).

## 명령어
- 전부 확인: `pick/_dev/check.sh` (로직 테스트 → 빌드 → 정적 확인 → 서버 띄워 브라우저 확인). `check.sh quick`은 브라우저 없이, `check.sh sim`은 시뮬레이션을 다시 돌려 숫자가 그대로인지.
  - 브라우저 확인 환경 변수: `PW_CHROME`(크롬 실행 파일), `PICK_FONT`(Pretendard 변수글꼴 .woff2 경로. CDN을 못 받는 곳에서 대신 줌), `PICK_SHOTS`(스크린샷 폴더), `PICK_SHOT_PREFIX`(스크린샷 이름 앞머리, 기본 final).
  - 묶음만 돌리기: 서버를 띄운 뒤 `python3 -B pick/_dev/e2e.py tools|guard|names|pages|cls|ads|misc|shots`. `guard`가 도는 중 명단 바꾸기·순서만 바꾼 링크·옛 링크·열 수 없는 링크·긴 링크·지우기와 되돌리기를 본다. `names`가 이름 고르기·꾸민 링크(보이지 않는 글자·풀어쓴 자모)·확인 코드·링크의 명단 가져오기·칸 고르기·긴 결과 이름(1366·390·320px)을 본다.
- 로직 테스트만: `node pick/tests/run.mjs` (약 20초, 외부 패키지 없음).
- 페이지 다시 만들기: `python3 -B pick/_dev/build.py`. 최신인지: `python3 -B pick/_dev/build.py --check`.
- **화면 글자를 고쳤으면** 조각 글꼴도 다시: `python3 -B pick/_dev/font.py` (끝에 build.py도 돌린다). 원본 글꼴은 jsDelivr에서 받거나 `PICK_FONT_SRC`로 준다. 안 돌려도 화면은 멀쩡하지만(빠진 글자는 CDN에서 받는다) `check.py`가 빠진 글자를 알려 주며 실패한다.
- 로컬 보기: `node pick/_dev/serve.mjs` → http://localhost:8442
- 기준값 다시 만들기: `python3 -B pick/tests/gen_fixtures.py`(numpy·scipy·regex 필요. regex는 이름 고르기의 파이썬 참조 구현이 유니코드 속성을 읽는 데 쓴다). 시뮬레이션: `node pick/_dev/sim_ladder.mjs`. 공유 그림: `python3 -B pick/_dev/og.py`.
- 배포: main에 푸시하면 GitHub Actions가 wrangler로 배포(`.deploy-actions`).

## 설계 결정
- **씨앗 = 난수기 상태 그대로**(32바이트, 섞는 단계 없음). 공개 기준 벡터(상태 1,2,3,4의 출력 10개)를 씨앗 넣는 문으로 바로 대조한다(값이 2^53을 넘어 BigInt로 견준다). 실제 씨앗은 전부 브라우저의 `crypto.getRandomValues`에서 오지만, 테스트에서 씨앗을 앞쪽 바이트만 바꿔 만들면 첫 출력이 같아진다(첫 출력은 상태의 둘째 칸에만 달려 있다).
- xoshiro256**는 암호용 난수기가 아니다(만든 쪽 설명). 사이트 글은 "씨앗은 브라우저에서 새로 받고, xoshiro256**는 같은 씨앗에서 같은 결과를 다시 만드는 데만 쓴다"고 적는다.
- **결과는 명단의 순서에 기대지 않는다(돌림판·제비뽑기·팀 나누기).** 씨앗이 고르는 것은 '이름을 코드 포인트 순으로 놓은 자리'다. 화면의 판·목록은 사용자가 넣은 순서 그대로 보여 주고, 정해진 사람의 칸에 멈춘다. 그래서 결과 링크 속 명단의 순서만 바꿔서는 다른 사람이 뽑힌 것처럼 꾸밀 수 없다. 사다리는 '누가 몇 번째 줄에 서는가'가 결과의 일부라 순서까지 같아야 하고, 화면과 글에 그렇게 밝힌다.
- **결과 링크가 보장하는 것은 하나**: 같은 씨앗 + 같은 사람들이면 누구나 같은 결과를 다시 계산할 수 있다. 보장하지 않는 것: 여러 번 뽑아 마음에 드는 링크만 보내기, 뽑기 전에 명단 자체를 바꾸기(→ 명단을 먼저 공개하라고 안내). 글·FAQ·소개가 이 범위를 넘는 말을 하지 않게 한다.
- **이름은 들어오는 모든 길에서 한 가지 꼴로 고른다**(`core/name.js`의 `cleanName`. 입력칸·붙여 넣기·링크·사다리 아래 칸·쪽지에 쓴 말). 화면에 똑같이 보이는 이름이 글자열로는 다르면(폭 없는 공백이 끼었거나 풀어쓴 자모) 자리가 달라져 다른 사람이 뽑히기 때문이다. 정해진 자리, 겹친 이름, 확인 코드는 전부 고른 꼴로 따진다. 그림 글자(이모지)는 깨지지 않는다: 그림 글자를 잇는 U+200D, 그림 모양으로 바꾸는 U+FE0F, 잉글랜드·스코틀랜드·웨일스 깃발의 꼬리표는 뜻이 있는 자리에서만 남긴다. 남는 틈은 둘: 눈에 같아 보이는 다른 글자(라틴 a와 키릴 а), 나란한 그림 글자 사이의 U+200D. 이것은 확인 코드로만 가려진다(글에도 그렇게 적는다). 페르시아어의 U+200C, 인도계 글자의 U+200D, 몽골 글자·한자의 변형 선택자는 지워진다(모양이 조금 달라질 수 있다).
- **확인 코드(평가의 '명단 지문')**: 명단 확인 코드 = SHA-256(고른 이름을 코드 포인트 순으로 놓고 줄바꿈으로 이은 글의 UTF-8)의 앞 8자리. 사람들이 같으면 순서가 달라도 같다. 사다리 확인 코드 = SHA-256(이름을 줄 순서대로 잇고, 빈 줄 하나 뒤에 아래 칸을 적은 순서대로 이은 글)의 앞 8자리(순서를 탄다). 명단 칸 아래(`#listcode`, 첫 HTML에는 build.py가 예시 명단의 코드를 넣는다)와 결과 곁(`#fp`, 그 결과를 만든 명단의 것)에 '8명 · 9cfbab72' 꼴로 보인다. 숫자·동전·주사위에는 없다. 8자리(32비트)라 우연히 같을 일은 약 43억 분의 1이고 암호 수준의 증명은 아니라고 소개·가이드에 적는다. **계산 규칙을 바꾸면 사람들이 미리 올려 둔 코드와 안 맞게 되므로 바꾸지 않는다.**
- **링크로 연 결과의 표시는 세 가지**(`readShare`의 `mark`): `ok` = '링크의 결과 그대로'(빨간 도장), `cleaned` = '정리한 명단으로 다시 계산한 결과'(링크 속 이름이 고른 꼴이 아니어서 고쳐 읽었을 때. 알림 "이 링크의 명단에 보이지 않는 글자가 들어 있어 정리했어요…"), `legacy` = '옛 방식 링크 · 확인 표시 없음'(형식 1. 알림 "옛 방식의 링크예요. 지금 방식으로는 확인할 수 없어요…"). 뒤의 둘은 회색 점선 표시이고 도장 연출이 없다. 휴대폰에서 표시는 결과 머리 줄(20px) 안에 들어가는 크기로 둔다(더 크면 이름이 두 줄일 때 아래 단추 줄이 밀린다. `e2e.py names`가 표시 세 가지 × 두 언어 × 390·320px에서 잰다. 표시 글을 길게 고치면 320px에서 다음 줄로 넘어가는지 볼 것). 형식 번호는 2 그대로다(올리지 않았다): 이미 만든 형식 2 링크 가운데 고른 꼴이 아닌 이름이 든 것만 '정리한 결과'로 열리고, 그 결과는 링크를 만든 화면과 다를 수 있다(알림에 적는다). 공백을 다듬지 않은 이름이나 제어 문자가 든 링크는 전처럼 열지 않는다(이 사이트가 만든 적 없는 꼴).
- **공유 링크 형식 번호**: 1 = 처음 형식(넣은 순서가 자리), 2 = 지금(정해진 자리). 난수를 쓰는 순서나 뽑는 방식을 바꾸면 번호를 올리고 옛 번호는 옛 방식으로 계속 열리게 둔다(형식 1 링크는 `legacy`로 열고 "옛 방식 링크"라고 알린다). `tests/golden.json`의 고정값이 바뀌면 이 일이 일어난 것이다. 사다리·숫자·동전·주사위는 1과 2가 같은 방식.
- 링크 길이 한도 40만 자(`MAX_HASH`): 넘으면 만들지 않고 "링크로 담기엔 명단이 너무 길어요"라고 알린다(만들어 준 링크는 전부 열린다). 4,000자를 넘으면 복사할 때 길다고 알리고, 최근 결과에는 링크를 저장하지 않는다.
- **돌림판은 결과를 먼저 정하고 그 칸에 멈추는 각도를 계산한다.** 멈춘 위치로 결과를 읽지 않는다. 바늘은 오른쪽(3시). 칸 안에서 멈출 자리(0.10~0.90)와 바퀴 수(5~7)도 씨앗에서 나온다.
- **돌리기를 누른 순간의 명단·씨앗·결과를 한 묶음으로 잡는다**(`tools/wheel.js`의 `spinning`). 판의 강조 칸, 발표 이름, '빼고 다시', 결과 링크, 최근 결과가 전부 그 묶음에서 나온다. 도는 동안에는 명단 칸(readOnly)과 그 단추들을 잠그고 잠겼다고 보여 준다. 사다리·제비뽑기·팀도 결과는 만든 순간의 명단을 잡아 둔 것이고, 명단이 바뀌면 그 결과를 지운다(사다리는 길을 따라가는 도중이어도).
- **'이 사람 빼고 다시'는 명단 칸의 글과 저장된 명단을 건드리지 않는다.** 뺀 사람은 메모리에만 적고(`out`) 판에서만 뺀다. 명단 아래에 '판에서 뺀 사람'으로 보이고 '마지막 한 명 되돌리기'·'모두 되돌리기'가 있다. 새로 열면 모두 판으로 돌아온다.
- '명단 지우기'는 묻지 않고 지우되 **되돌릴 수 있다**(다음 변경 전까지). 지운 직후 '기록도 지우기'는 **최근 결과 기록에 그 명단의 이름이 남아 있을 때만** 보여 준다(`historyHolds`: 기록의 링크 속 명단, 링크가 없는 기록은 요약 글).
- **링크로 연 명단은 '링크의 명단'으로 따로 둔다**(`list.shared`): 읽기 전용, 회색 점선 칸, 저장하지 않는다. 고치려 하면(누르기·글자 치기·붙여 넣기·섞기 같은 단추) "이 명단을 내 명단으로 가져올까요?"를 묻고, '가져오기'를 눌러야 저장된다. 가져온 뒤에는 '전 명단으로 되돌리기'가 그 화면을 닫을 때까지 남는다(전에 저장한 명단이 있었을 때). '내 명단으로' 단추는 링크의 명단을 치우고 저장해 둔 명단(없으면 예시)으로 돌아간다. 안내 줄의 상태 순서: 잠김 > 지움(되돌리기) > 묻는 중 > 링크의 명단 > 가져옴 > 예시 > 내 명단.
- **여러 칸 붙여 넣기**: 탭이 든 줄이 절반 이상이면 "어느 칸을 쓸까요?"와 칸마다 단추('2번째 칸: 김민준, 이서연 …')를 보여 준다. 번호뿐인 칸은 뒤로 보낸다. 누르면 그 칸만 남는다.
- '지금까지 뽑힌 순서': 최근 60개, 명단에서 없어진 이름은 빠진다(명단을 통째로 바꾸면 새로 시작). 휴대폰에서는 옆으로 미는 한 줄.
- **큰 결과 이름은 자르지 않는다**(`fitName`): 큰 글자부터 한 단계씩 줄여 보며(`.result-name[data-fit]` 0~3, 단계마다 줄 수 한도 `--lines`) 들어가는 첫 단계를 쓴다. 마지막 단계에서도 넘치면 3줄에서 줄이고 바로 아래(`#rfull`)에 전체 이름을 작은 글자로 한 번 더 보여 준다. 이름 자리의 높이는 미리 잡아 둔다(컴퓨터 136px, 휴대폰 92px. 전체 화면은 더 크게). 컴퓨터의 결과 기둥은 이름 가운데가 판 가운데(바늘 높이)에 오게 위쪽을 고정했다. 제비뽑기·팀·쪽지·사다리의 이름은 줄을 바꿔 다 보여 주고 길이에 따라 글자를 한두 단계 줄인다(`nameEl`). 판 위의 이름(좁은 칸)은 아래 줄대로 줄이거나 자른다.
- 열 수 없는 링크 알림이 떠 있는 동안 돌리기를 누르면 이유를 알려 준다("링크를 열 수 없어 멈춰 있어요. 위의 안내를 닫으면 내 명단으로 돌릴 수 있어요." + 알림이 한 번 흔들린다).
- 돌림판 그리기: 멈춰 있을 때는 캔버스 안에 지금 각도로 그리고(왼쪽 절반의 이름은 뒤집어 써서 거꾸로 보이지 않게), 도는 동안만 그려 둔 캔버스를 CSS transform으로 돌린다. 긴 이름은 글자를 72%까지(9px 아래로는 안) 줄이고, 그래도 넘치면 자른다. 칸이 얇아 이름이 안 보일 때는 뽑힌 칸을 넓혀 다시 그린다.
- **사다리는 아래 칸을 먼저 섞는다.** 사다리만으로는 출발 자리 근처에 도착하기 쉽다(8명·14층 사다리에서 맨 끝 사람이 바로 아래 칸에 24.8%, 공평하면 12.5%). 숫자는 `_dev/sim_ladder.json`, 설명은 가이드 글.
- 사다리 규칙: 2~30명, 8·14·24층(적게·보통·많이). 층마다 왼쪽부터, 맨 왼쪽 틈 1/3, 그다음은 왼쪽 틈이 비었을 때만 1/2(모든 틈의 가로줄 확률이 1/3로 같음). 같은 층에 이웃한 가로줄 없음. 3층 이상이면 모든 틈에 하나 이상. 글에서 쓰는 말: 세로줄·가로줄·층(가로줄을 놓는 높이)·칸(아래의 결과 자리).
- 팀: '한 팀 최대 인원'이면 팀 수 = 올림(인원 ÷ 최대). 인원 차이는 최대 1.
- 랜덤 숫자: 화면 입력은 15자리까지(±999,999,999,999,999), 한 번에 10,000개. 중복 없이 뽑기는 Floyd의 방법 뒤 섞기. 숫자·동전·주사위는 입력이 틀리면 앞 결과를 지우고 경우에 맞는 안내만 보여 준다.
- 열 수 없는 링크(잘림·새 형식·너무 김·다른 도구의 링크)는 도구 위에 겹쳐 띄우는 알림으로 알린다(끼워 넣지 않아 화면이 안 밀린다). 돌림판은 그동안 내 명단을 판에 올리지 않는다.
- 이 기기에 저장하는 것(개인정보 처리방침과 같아야 한다. `check.py`가 코드의 키와 방침을 대조): `pick.list`(명단), `pick.history`(최근 결과 30개), `pick.sound`, `pick.lang`. 링크로 연 명단은 '가져오기'를 누르기 전에는 저장하지 않는다. 링크로 다시 본 결과는 기록에 더하지 않는다. 방침의 글꼴 설명도 실제와 같아야 한다(모든 쪽이 jsDelivr의 목록 파일(CSS) 하나를 받고, 조각은 자체 글꼴에 없는 글자가 있을 때만. `check.py`가 대조).
- 언어: 페이지 언어는 `<html lang>`. 브라우저 언어가 다르면 닫을 수 있는 띠만 화면 아래 가운데에 겹쳐 띄운다(자동으로 안 넘김). hreflang은 같은 역할의 짝에만(도구 7개·가이드 목록·소개·방침, 글은 사다리 글 한 쌍). 404.html은 하나라 두 언어를 다 담고 주소가 `/ko/`로 시작하면 한국어 칸만 남긴다.
- 휴대폰 순서: 판 → 결과(이름·단추·뽑힌 순서) → 내 명단 넣기 → 어떻게 뽑나요·소리·전체 화면. 컴퓨터의 결과 칸을 `display: contents`로 풀어 순서만 바꾼다. 결과가 5초 뒤에 떠도 아래가 안 밀리게 결과 자리(한국어 240px, 영어판과 360px 이하는 264px)를 미리 잡고, 돌리기 전에는 그 자리를 '여기에 이름이 나와요' 칸으로 보여 준다. 도는 동안에는 결과가 나온 뒤의 배치를 미리 쓴다(둘째 판부터 단추 줄이 움직이지 않게).
- 누르는 것은 휴대폰에서 44px 이상(문단 속 링크 제외). `e2e.py pages`가 모든 페이지에서 잰다.
- 화면 밀림(CLS): 저장된 명단은 입력칸 바로 뒤 인라인 스크립트가 첫 그림 전에 넣는다. 결과·단추 자리는 미리 잡아 두고 `visibility`로만 숨긴다. 광고 자리는 자리 바로 뒤 인라인 스크립트가 켠다. 글꼴이 오기 전 글꼴(Noto Sans CJK KR)은 `size-adjust`로 폭을 맞췄다(style.css 맨 위. 애플·윈도 기본 글꼴은 재지 못해 그대로).
- 글꼴: 이름표 순서는 `"PK Sans"`(조각, 같은 주소, preload) → `"Pretendard Variable"`(CDN 나눠 받기. 조각에 없는 글자만) → `"PK Fallback"` → 기기 글꼴. 조각은 언어판마다 하나(한국어 약 86KB, 영어 약 21KB)로, 한국어 첫 화면이 CDN 조각 16~18개(약 425~480KB)를 받던 것을 대신한다. 'Pretendard'는 예약된 글꼴 이름이라 조각 안의 이름은 'PK Sans'.
- 연출: 기본 반응은 `--t`(.16s)·`--ease` 하나로. 화려한 연출은 셋뿐: 전체 화면에서 결과가 나온 순간의 색종이, 링크로 연 결과의 확인 도장, 꼬리말 '만든 곳' 줄의 작은 돌림판(화면에 들어오면 한 번). 돌림판이 도는 것과 사다리 길 따라가기는 도구의 본체. 동작 줄이기면 회전 없이 결과만.
- 꼬리말의 루멘랩 링크는 글 한 줄('만든 곳 루멘랩 · 다른 앱과 도구 보러 가기') + 작은 판이다. 테두리 상자·알약 모양은 광고처럼 보여서 쓰지 않는다.
- 소리는 Web Audio로 만든 짧은 소리(파일 없음). 누르기 전에는 소리 장치를 만들지 않는다. 기본 켬, 단추로 끔.
- 전체 화면 단추는 `document.fullscreenEnabled`인 기기에서만 보인다.
- 광고 자리는 돌리기·뽑기 단추에서 150px 넘게, 다른 단추·입력칸에서 40px 넘게 떨어뜨린다(`e2e.py ads`가 잰다). 자리 폭은 본문 글 기둥과 같다. 404·소개·방침·가이드 목록에는 광고 코드가 없다.

## 주의할 점
- **소스에 보이지 않는 글자를 그대로 적지 않는다.** `name.js`의 범위와 테스트의 본보기는 `\u200b` 같은 이스케이프로 적는다(`check.py`가 `assets/**/*.js`의 코드 줄에 박힌 보이지 않는 글자를 실패시킨다). AI 도구로 파일을 쓸 때 `\uXXXX`가 글자 그대로로 바뀌어 들어가는 일이 있었다(2026-10-10): 쓴 뒤 `cat -A`나 `check.py`로 확인하고, 파이썬에서는 `'\N{ZERO WIDTH SPACE}'` 꼴이 안전하다.
- 이름 고르기(`cleanName`)나 확인 코드 규칙을 고치면 `tests/gen_fixtures.py`의 파이썬 참조 구현도 같이 고치고 기준값을 다시 만든다. 로직 테스트가 둘을 587건 + 모든 코드 포인트로 대조한다. 확인 코드 규칙은 바꾸지 않는 것이 원칙이다(위 '설계 결정').
- 화면 글자를 고치면 `content.json`(또는 `_dev/pages/`·`_dev/articles/`)만 고치고 빌드를 다시 돌린다. 그다음 `font.py`. FAQ는 화면과 FAQPage가 같은 데이터에서 나온다.
- 글에 바깥 사실을 더할 때는 공식 출처를 확인한 것만, 링크와 확인한 날을 같이 적는다(`check.py`가 본다). 지금 글의 바깥 사실: MDN 두 문서(crypto.getRandomValues, Math.random), xoshiro256**를 만든 쪽 페이지(prng.di.unimi.it: 암호용 아님), 기준 벡터(Rust rand_xoshiro의 reference 테스트), Fisher–Yates의 출처(Durstenfeld 1964, Knuth TAOCP 2권 알고리즘 P), 사다리의 다른 이름(아미다쿠지, Ghost Leg), Cloudflare Web Analytics 안내 페이지. 추첨·경품의 법 이야기는 쓰지 않는다.
- 글·소개의 날짜는 '마지막 확인'(실제로 본문을 확인한 날). sitemap의 lastmod는 `build.py`의 `MODIFIED`·`UPDATED`에 실제로 본문·구조화 데이터·링크를 고친 날만 적는다(배치·CSS만 바꾼 날은 아님).
- 영어 페이지에 한글을 쓰려면 `lang="ko"`로 감싼다(안 감싸면 `check.py`가 실패). 화면 코드가 데이터에서 넣는 글자는 `e2e.py tools`가 눌러 본 뒤 다시 확인한다.
- 광고 코드가 있는 실제 주소를 자동으로 열지 않는다. 로컬에서도 `e2e.py`는 광고 요청을 정규식으로 막는다. 실제 주소에서는 Cloudflare가 방문 통계 스크립트를 끼워 넣는다(우리 HTML에는 없다. 방침에 적혀 있다).
- `tests/run.mjs`의 균등성 검정은 씨앗이 고정이라 늘 같은 결과다(가끔 실패하는 테스트가 아니다). 실패하면 로직이 바뀐 것이다.
- 폴더 안에 `node_modules`·`__pycache__`·`.wrangler`를 남기지 않는다(파이썬은 `-B`로 돌린다. `check.sh`가 끝에 지운다).
