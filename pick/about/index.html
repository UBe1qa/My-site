About Pickboard

Last checked 2026-10-10

Pickboard is a free set of tools for picking at random: a wheel, a ladder game, a name picker, a team generator, random numbers, a coin and dice. It is made by Lumen Lab, a small studio in Korea that builds apps and web tools. There is no sign-up, and the list you type is not sent to a server.

How a pick is made

Every time you press the button, the page asks your browser for a new 32-byte value with crypto.getRandomValues(). We call that value the seed. MDN describes the method as giving cryptographically strong random values, and also notes that browsers do not use a truly random number generator for it but a pseudo-random generator seeded with enough entropy (MDN: Crypto.getRandomValues(), checked 2026-10-10). So we do not call the picks “truly random” either. We do not use Math.random(), which MDN says does not provide cryptographically secure random numbers (MDN: Math.random(), checked 2026-10-10).

A calculation called xoshiro256** turns the seed into the numbers a pick needs. It is deterministic, so the same seed with the same people and settings always gives the same result. That is what makes the result link work. xoshiro256** was written and published by David Blackman and Sebastiano Vigna. Their page presents it as an all-purpose generator and states that it is not a cryptographically secure one (prng.di.unimi.it, checked 2026-10-10). Here the seed is taken fresh from the browser on every press, and xoshiro256** is used only to rebuild the same result from the same seed. Do not use this site to make passwords or keys.

Whole numbers are taken without bias. To pick one of n items the page draws only as many random bits as n needs and discards any value that is n or more, then draws again. It never divides and keeps the remainder, which would make some items very slightly more likely.

Orders, teams and multi-name draws use the Fisher–Yates shuffle in the form published by Richard Durstenfeld in 1964 and described as Algorithm P in Donald Knuth’s The Art of Computer Programming, volume 2. Every possible order is equally likely.

The wheel, the name picker and the team generator do not pick by the order you typed the list in. They work from the names placed in a fixed order, sorted by character code. So with the same seed and the same people, everyone gets the same result however the list was ordered. The ladder game is the exception: who stands on which line, and the order of the bottom-row items, are part of the result, so both orders have to match too.

Names are put into one form before they are compared. Unicode normalization (NFC) joins decomposed letters, and invisible characters such as zero-width spaces and direction marks are removed. The characters that join emoji are kept only inside an emoji. This keeps two names that look identical on screen from being counted as different people.

What we do not build

There is no way to make a chosen name come up, on any tool, hidden or otherwise. The wheel decides the result first and then turns to it. A spin runs to the end with the list as it was when you pressed Spin, and the list is locked while the wheel turns. The ladder game shuffles its bottom row before building the ladder, because a plain ladder favours nearby positions; the ladder guide shows the numbers.

How it is tested

The picking code is separate from the screens and has more than 500 automated tests. The xoshiro256** code is compared, digit for digit, with ten published reference outputs (the values in the reference test of xoshiro256starstar.rs in Rust’s rand_xoshiro, checked 2026-10-10). The tests also draw 100,000 times with fixed seeds and apply a chi-square test to check that outcomes are even, shuffle lists thousands of times to confirm that the same people still get the same result, verify that every generated ladder is a one-to-one mapping, and confirm that a result link reproduces the same result. They were also run against deliberately broken versions of the code to make sure they fail when they should.

Recalculating a result yourself

A result link can be recalculated without this site. These are the rules you need.

  • Seed. The third dot-separated part of the link is 43 characters of base64url, which decode to 32 bytes. Read as four 64-bit numbers, least significant byte first, they are the starting state of xoshiro256**.
  • Picking one of n. Take as many of the top bits of the 64-bit output as it takes to write n−1 in binary. If the value is n or more, discard it and use the next output. If n is 1, no output is used.
  • Name form. Names inside a link made by this site are already in that form. If you start from your own list, remove invisible characters (Unicode Default_Ignorable_Code_Point) from each name, normalize to NFC, collapse runs of spaces and trim both ends. U+200D and U+FE0F stay when they are inside an emoji. The exact rule is in the public script /assets/core/name.js.
  • Positions. For the wheel, the name picker and the team generator, the names in that form sorted by Unicode code point are positions 0, 1, 2 and so on.
  • Wheel. The first number picked is the winning position. The next two only decide where inside the slot the wheel stops and how many turns it makes.
  • Shuffle (order, teams, slips). Lay out 0 to n−1 in order, then for i from n−1 down to 1, swap item i with an item picked from 0 to i. Teams are cut from the front of the shuffled row, team size by team size. Slips are numbered from 0, winning slips first, shuffled the same way and handed out by position.
  • Picking several names. For i from 0 upwards, swap item i with an item picked from i to n−1. Reading from the front gives the names in the order drawn.
  • Check code. The list check code is the first 8 hexadecimal characters of the SHA-256 of the names, sorted by code point and joined with line feeds (U+000A), encoded as UTF-8. The ladder check code does the same with the names in line order joined with line feeds, then two line feeds, then the bottom-row items in the order written, joined with line feeds.

The order used by the ladder, numbers, coin and dice is in the site’s public scripts: rng.js, pick.js and ladder.js under /assets/core/.

Limits worth knowing

A result link guarantees one thing: with the same seed and the same people, anyone can recalculate the same result. It does not guarantee two others. It cannot show whether someone drew several times and sent only the link they liked, and on its own it cannot show whether the list was changed before the draw. For a draw that matters, publish the list and its check code first, and agree on one draw in advance or draw on a screen everyone can see. The check code has eight characters, so two different lists share a code by chance about once in 4.3 billion (1 in 16 to the 8th power). A list dressed up with look-alike letters, such as Latin a and Cyrillic а, gets a different code and so shows up. It is not cryptographic proof, however, and would not stop someone who deliberately computed a fake list to match the code. This site is for classrooms, meetings and games, and is not meant for draws that need a formal audit.
