공평뽑기 소개

마지막 확인 2026-10-10

공평뽑기는 무작위로 뽑는 일을 돕는 무료 도구 모음이에요. 돌림판, 사다리타기, 제비뽑기, 팀 나누기, 랜덤 숫자, 동전, 주사위가 있어요. 앱과 웹 도구를 만드는 루멘랩(Lumen Lab)이 만들었어요. 가입이 없고, 넣은 명단은 서버로 보내지 않아요.

뽑는 방식

단추를 누를 때마다 브라우저에 crypto.getRandomValues()로 32바이트짜리 새 값을 달라고 해요. 이 값을 ‘씨앗’이라고 불러요. MDN은 이 기능이 암호학적으로 강한 난수 값을 준다고 설명해요. 브라우저가 진짜 난수 발생기 대신, 충분한 엔트로피로 씨앗을 준 의사 난수 생성기를 쓴다는 점도 함께 적고 있어요(MDN: Crypto.getRandomValues(), 2026-10-10 확인). 그래서 여기서도 ‘완전한 무작위’라고 하지 않아요. Math.random()은 쓰지 않아요. MDN은 이 함수가 암호학적으로 안전한 난수를 주지 않는다고 적고 있어요(MDN: Math.random(), 2026-10-10 확인).

씨앗에서 뽑기에 필요한 숫자를 만드는 일은 xoshiro256**라는 계산이 맡아요. 정해진 대로만 움직이는 계산이라서 씨앗, 사람들, 설정이 같으면 결과도 늘 같아요. 결과 링크가 되는 이유가 이것이에요. xoshiro256**는 David Blackman과 Sebastiano Vigna가 만들어 공개한 계산법이에요. 만든 사람들의 페이지는 이것을 여러 용도에 두루 쓰는 생성기로 소개하면서, 암호용으로 안전한 생성기는 아니라고 밝히고 있어요(prng.di.unimi.it, 2026-10-10 확인). 여기서는 씨앗을 누를 때마다 브라우저에서 새로 받고, xoshiro256**는 그 씨앗에서 같은 결과를 다시 만드는 데만 써요. 비밀번호나 암호 키를 만드는 데는 이 사이트를 쓰지 마세요.

정수는 치우침 없이 뽑아요. n개 중 하나를 고를 때 n에 필요한 만큼의 비트만 뽑고, n 이상이 나오면 버리고 다시 뽑아요. 나눈 나머지를 쓰는 방식은 일부 항목이 아주 조금 더 잘 나오게 되는데, 그 방식을 쓰지 않아요.

순서 정하기, 팀 나누기, 여러 명 뽑기는 피셔–예이츠(Fisher–Yates) 섞기를 써요. 리처드 더스텐펠드가 1964년에 발표한 꼴이고, 도널드 커누스의 『The Art of Computer Programming』 2권에 알고리즘 P로 실려 있어요. 가능한 모든 순서가 같은 확률이에요.

돌림판, 제비뽑기, 팀 나누기는 명단을 적은 순서가 아니라 이름을 글자 코드 순으로 놓은 자리를 기준으로 뽑아요. 그래서 씨앗과 사람들이 같으면 명단을 어떤 순서로 넣었든 같은 사람이 같은 결과를 받아요. 사다리타기만은 누가 몇 번째 줄에 서는지와 아래 칸을 적은 순서가 결과의 일부라서, 줄 순서와 아래 칸 순서까지 같아야 같은 결과예요.

이름은 읽을 때 한 가지 꼴로 고른 뒤에 견줘요. 유니코드 정규화(NFC)로 풀어쓴 자모와 결합 글자를 한 글자로 합치고, 폭 없는 공백이나 방향 표시처럼 보이지 않는 글자는 지워요. 이모지를 잇는 글자는 이모지 안에 있을 때만 남겨요. 화면에 똑같이 보이는 이름이 글자만 달라서 다른 사람으로 세어지는 일을 막으려는 것이에요.

만들지 않는 것

어떤 도구에도 특정 이름이 나오게 하는 기능은 없어요. 숨겨진 것도 없어요. 돌림판은 결과를 먼저 정하고 그 칸으로 돌아가요. 돌리기를 누른 순간의 명단으로 끝까지 가고, 도는 동안에는 명단을 잠가요. 사다리타기는 사다리만으로는 가까운 자리가 유리해서 아래 칸을 먼저 섞어요. 숫자는 사다리타기 가이드에 있어요.

검증하는 법

뽑는 코드는 화면과 따로 있고 자동 테스트가 500개 넘게 붙어 있어요. xoshiro256** 구현은 공개된 기준값 10개와 숫자 하나까지 같은지 대조해요(Rust rand_xoshiro의 xoshiro256starstar.rs에 실린 reference 테스트 값, 2026-10-10 확인). 씨앗을 고정해 10만 번씩 뽑은 뒤 카이제곱 검정으로 고르게 나오는지 보고, 명단을 수천 번 뒤섞어도 같은 사람이 뽑히는지, 만든 사다리가 전부 일대일 대응인지, 결과 링크가 같은 결과를 다시 만드는지 확인해요. 코드를 일부러 망가뜨린 판에서 테스트가 실패하는지도 확인했어요.

다른 프로그램으로 다시 계산해 보려면

결과 링크의 결과는 이 사이트 없이도 다시 계산할 수 있어요. 필요한 규칙은 이래요.

  • 씨앗. 링크에서 점으로 나뉜 셋째 덩어리 43자를 base64url로 풀면 32바이트예요. 8바이트씩 끊어 낮은 자리부터 읽은 64비트 수 네 개가 xoshiro256**의 처음 상태예요.
  • n개 중 하나 고르기. n−1을 이진수로 적는 데 필요한 비트 수만큼, 64비트 출력의 맨 위쪽 비트를 읽어요. 그 값이 n 이상이면 버리고 다음 출력으로 다시 해요. n이 1이면 출력을 쓰지 않아요.
  • 이름 고르기. 이 사이트가 만든 링크 속 이름은 이미 고른 꼴이에요. 명단을 직접 넣어 계산한다면 이름마다 보이지 않는 글자(유니코드의 Default_Ignorable_Code_Point)를 지우고 NFC로 정규화한 다음 이어진 공백을 하나로 줄이고 앞뒤 공백을 떼요. 이모지 안의 U+200D와 U+FE0F는 남겨요. 정확한 규칙은 공개 스크립트 /assets/core/name.js에 있어요.
  • 자리. 돌림판, 제비뽑기, 팀 나누기는 고른 이름을 유니코드 코드 포인트 순으로 놓은 것이 0번부터의 자리예요.
  • 돌림판. 처음 고른 수가 뽑힌 자리예요. 이어서 고르는 두 수는 칸 안에서 멈출 위치와 도는 바퀴 수라서 누가 뽑히는지와는 상관없어요.
  • 섞기(순서 정하기, 팀, 쪽지). 0번부터 n−1번까지를 차례로 놓고, i를 n−1부터 1까지 내리면서 0부터 i까지에서 고른 칸과 i번 칸을 맞바꿔요. 팀은 섞은 줄을 앞에서부터 팀 인원대로 끊어요. 쪽지는 0번부터 번호를 붙이고(앞 번호가 당첨) 같은 방법으로 섞어 자리 순서대로 한 장씩 줘요.
  • 여러 명 뽑기. i를 0부터 올리면서 i부터 n−1까지에서 고른 칸과 i번 칸을 맞바꿔요. 앞에서부터가 뽑힌 순서예요.
  • 확인 코드. 명단 확인 코드는 고른 이름들을 코드 포인트 순으로 놓고 줄바꿈 글자(U+000A)로 이은 글의 UTF-8 바이트에 SHA-256을 적용한 값의 앞 8자리(16진수)예요. 사다리 확인 코드는 이름을 줄 순서대로 줄바꿈으로 잇고, 줄바꿈 두 개 뒤에 아래 칸을 적은 순서대로 줄바꿈으로 이은 글에 같은 계산을 한 값이에요.

사다리, 숫자, 동전, 주사위의 순서는 이 사이트의 공개 스크립트(/assets/core/ 폴더의 rng.js, pick.js, ladder.js)에 그대로 있어요.

알아 둘 한계

결과 링크가 보장하는 것은 하나예요. 같은 씨앗과 같은 사람들이면 누구나 같은 결과를 다시 계산할 수 있다는 것이에요. 보장하지 못하는 것은 두 가지예요. 여러 번 뽑아 보고 마음에 드는 링크만 보냈는지, 그리고 뽑기 전에 명단 자체를 바꿨는지는 링크만으로 알 수 없어요. 그래서 중요한 뽑기라면 명단과 확인 코드를 먼저 공개해 두고, 한 번만 뽑는다고 미리 정하거나 모두가 보는 화면에서 뽑으세요. 확인 코드는 여덟 글자라서 서로 다른 명단이 우연히 같은 코드가 될 가능성은 약 43억 분의 1(16의 8제곱 분의 1)이에요. 눈에 같아 보이는 다른 글자(라틴 글자 a와 키릴 글자 а 같은 것)로 꾸민 명단도 코드가 달라져서 드러나요. 다만 작정하고 계산해 코드까지 맞춘 가짜를 막는 암호 수준의 증명은 아니에요. 이 사이트는 교실, 모임, 놀이에 쓰려고 만든 것이고, 정해진 절차와 감사가 필요한 추첨에는 맞지 않아요.

저장하는 것

명단, 최근 결과, 소리 설정, 언어 안내를 닫았는지는 이 브라우저에만 저장해요. 정확한 저장 항목과 방문 통계, 광고가 어떻게 동작하는지는 개인정보 처리방침에 있어요.
