# 체크벤치 / Checkbench (check)

브라우저에서 바로 하는 기기 테스트 8종: 키보드, 마우스, 마이크, 웹캠, 스피커, 불량화소, 주사율, 게임패드. 첫 화면은 일곱 기기를 한 번에 보는 점검판이다.
정적 사이트(배포 때 빌드 없음, 서버 코드 없음). 마이크 소리·녹음·카메라 영상·사진은 탭 안에서만 다루고 어디에도 보내지 않는다.
- 주소: https://check.lumenlab.page (Worker `check`, workers.dev 끔). 영어 `/`(x-default), 한국어 `/ko/`. 모든 쪽이 hreflang 짝.
- 상징은 표시등(작은 불): 아직 안 봄(회색 점) / 반응함(청록 + ✓) / 의심(주황 + !) / 못 엶(빨강 + ×). 색 하나에 뜻 하나(청록 = 반응함).

## 폴더
- `_dev/build.py` **모든 HTML을 만든다**: `python3 -B check/_dev/build.py`(→ "built N pages"), `--check`는 낡았는지만 본다. 자판 그림(SVG)은 `assets/ck-keys.js`의 배열 표를 node로 읽어 그려 첫 HTML에 넣는다(그래서 만들 때 node가 필요하다). 만든 HTML·`sitemap.xml`·`rss.xml`·`404.html`은 손으로 고치지 않는다. 설명 글 속 `{thr:kb}`·`{thr:mouse}`는 지금 기준 값이 들어가는 자리다(설정을 바꾸면 화면 코드가 따라 바꾼다). 가이드 글의 가운데 광고 자리는 글 한가운데에 가장 가까운 소제목 앞에 넣는다.
- `_dev/content.json` 화면 글자 전부: `ui`(공통), `t`(화면 코드가 쓰는 문장. 쪽마다 `#ck` JSON으로 들어간다), `home`, `tools`(8개: 제목·설명·순서·설명 글·FAQ), `about`, `privacy`. 도구에 `sources`(label·url·checked)를 적으면 FAQ 아래에 출처 줄이 생기고 `check.py`가 링크와 확인한 날을 본다(공식 출처를 확인한 사실에만 쓴다).
- `_dev/articles.json` 가이드 글(영어·한국어 따로 쓴 같은 주제 4쌍, `pair`로 hreflang 짝). `sources`에 적은 출처 링크와 확인한 날이 화면에 있는지 `check.py`가 본다. `banned`는 확인하지 못해 화면에 쓰면 안 되는 낱말·문장(사이트 전체 화면 글에서 찾는다).
  - 글의 표는 `build.py`의 `wrap_tables`가 감싼다: 첫 칸 말고 전부 짧으면 `tbl--tight`(그 칸들은 줄을 안 바꿈), 긴 글 칸이 둘 이상이고 칸이 3개 이하면 `tbl--cards`(휴대폰에서 줄마다 카드, 칸 이름은 `data-th`), 그 밖은 칸 안에서 줄을 바꾼다. 옆으로 넘치면 넘치는 쪽 가장자리에 그림자가 보인다. 글에는 이 도구가 실제로 하는 일, 테스트로 구한 예시, 출처를 확인한 사실만 쓴다(제조사 교환 기준·불량화소 개수 기준·수리 방법은 싣지 않는다).
- `assets/ck-keys.js` 자판 배열 표(`full` ANSI 104, `iso` 105, `tkl` 87, `mac` 78)와 키 기록기(채터링 의심, 동시에 눌린 최대 수, 눌린 채 있는 키, 안 눌린 키, 누름 없이 뗌만 온 키, 눌린 채로 두지 않는 키). `assets/ck-measure.js` 중앙값, 주사율·폴링 추정과 '프레임이 고른가', 소리 크기(dBFS)와 잘림, 좌우 테스트 음, 주파수 훑기, 스틱 쏠림·떨림, 축의 가만히 둔 값, 해상도 이름, 장치 오류 나누기. **둘 다 화면(DOM)을 모른다.**
- `assets/app.js` 공통(상태 불, 다른 언어 안내 띠, 광고 자리, 루멘랩 연출) + 권한 없이 되는 것(키보드, 마우스, 주사율, 게임패드). `assets/media.js` 마이크·카메라·스피커. `assets/screen.js` 불량화소 전체 화면. 쪽마다 필요한 파일만 싣는다(`build.py`의 `SCRIPTS`).
- `assets/style.css` 색·모서리·움직임 값은 `:root` 토큰(밝게·어둡게).
- `assets/fonts/` 화면 글자만 담은 조각 글꼴 `ck-en-<지문>.woff2`(약 22KB)·`ck-ko-<지문>.woff2`(약 89KB)와 라이선스 전문 `OFL.txt`. `_dev/font.py`가 만들고(fonttools·brotli 필요, 원본은 `CK_FONT_SRC=<PretendardVariable.woff2>` 또는 jsDelivr), 파일 이름·글자 범위를 `_dev/fonts.json`에 적는다. `build.py`가 그것으로 `<head>`에 preload와 `@font-face`("CK Sans", `font-display: optional`)를 넣는다. 바깥 글꼴 주소(CDN)는 쓰지 않는다. 'Pretendard'는 예약된 글꼴 이름이라 조각 안의 이름은 'CK Sans'다.
- `_headers` 응답 머리말(Cloudflare 정적 자산): `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, 글꼴 조각 1년 저장. 광고·마이크·카메라를 막을 수 있는 정책 머리말(콘텐츠 보안 정책, 권한 정책)은 넣지 않는다. `.assetsignore`에 넣으면 적용되지 않는다.
- `assets/ads-config.js` 애드센스: client 들어 있음, 수동 광고 단위 번호(slots)는 비어 있음. 자리 2곳(mid, bottom). localhost나 `?adpreview`면 빗금 상자. `<head>`에서 바로 실행돼 자리 높이를 첫 그림 전에 잡는다.
- `tests/` 로직 시험(`run.mjs`), 기준값 만들기(`gen_cases.py` → `cases.json`, `gen_ref_codes.py` → `ref-us-codes.json`), 일부러 틀리게 바꾸기(`mutants.mjs`). `gen_cases.py`에 기준값을 더할 때는 맨 뒤에서 난수를 뽑는다(앞의 기준값이 바뀌지 않게).
- `og.png`·`og-ko.png`는 `_dev/og.py`가 `_dev/og.html`을 찍는다. `favicon.*`·`apple-touch-icon.png`는 로고(어두운 둥근 네모 + 켜진 불)를 그린 것.

## 명령어
- 전부 확인: `check/_dev/check.sh` (로직 시험 → 빌드가 최신인지 → 정적 검사 → 문법). 화면 확인까지: `PY=<playwright 깔린 파이썬> check/_dev/check.sh e2e [스크린샷 폴더]`.
- 로직 시험: `node check/tests/run.mjs` · 변이 확인: `node check/tests/mutants.mjs` · 기준값 다시 만들기: `python3 check/tests/gen_cases.py`
- 로컬 보기: `node check/_dev/serve.mjs` → http://localhost:8444 (폴더 → index.html, 없는 주소 → 404.html, `_dev` 막음)
- 화면 확인만: `python3 -B check/_dev/e2e.py [스크린샷 폴더]`. `CK_ONLY=home,keyboard`처럼 묶음을 골라 돌릴 수 있다(`all_pages, home, keyboard, quirks, mouse, mic_cam_spk, screen_pad, late_shift, others, denied`). 가짜 마이크에는 보통 크기의 소리 파일을 만들어 넣는다(크롬의 기본 가짜 소리는 꼭대기까지 꽉 차 '너무 커요'로 나온다).
- 조각 글꼴 다시 만들기(화면 글자를 고쳤을 때): `python3 -B check/_dev/font.py` (끝에 `build.py`도 돌린다). 안 돌리면 `check.py`가 빠진 글자를 알려 주며 실패한다.
- 배포: `.deploy-actions`가 있어 main에 푸시하면 GitHub Actions가 wrangler로 배포한다.

## 이 사이트의 기준(공식 표준이 아니다. 화면과 소개에 그대로 밝힌다)
- 키보드 채터링 의심: 같은 키를 뗀 뒤 30ms가 되기 전에 다시 눌림(딱 30ms는 세지 않는다. 5~200ms로 바꿀 수 있음, `ck.chatter`).
- 마우스 더블클릭 의심: 같은 단추를 뗀 뒤 50ms가 되기 전에 다시 눌림(바꿀 수 있음, `ck.dblclick`).
- 마우스가 1초에 알려 주는 횟수: 움직이는 동안 받은 이벤트 시각으로 추정. 250ms 안쪽의 가장 촘촘한 창. 흔한 값(125~8000)의 10% 안이면 '약'.
- 주사율: 화면 120장 간격의 중앙값. 흔한 값의 1% 안이면 '약 N Hz'. 중앙값의 ±15% 안에 든 화면이 75%보다 적으면(`CK.REFRESH_STEADY`) 값을 단정하지 않고 "프레임이 고르지 않아 정확히 못 쟀어요"라고 한다(흔한 값에 가까울 때만 '약 N Hz로 보여요').
- 소리 크기: 표본 1.0 = 0 dBFS(꽉 찬 사인파의 RMS는 -3.01 dBFS). -45 dBFS를 넘은 화면이 세 번 쌓이면 '소리를 잡아요'. 꼭대기에 닿은 표본이 0.5% 이상인 화면(`CK.MIC_CLIP_SHARE`)이 최근 3초 안에 세 번 있으면 '너무 커요'.
- 테스트 음: 크기 0.1에서 시작, 0.5를 넘지 못한다. 올라가는 소리는 40Hz → 16,000Hz, 8초.
- 스틱 쏠림: 가만히 둔 위치의 평균. 5% 미만 가운데, 5% 이상 15% 미만 조금 쏠림, 15% 이상 쏠림. 판정은 화면에 보이는 자리(0.1%)로 반올림한 값으로 한다('5.0%'라고 보여 주면서 '가운데'라고 하지 않게). 떨림: 그 평균에서 가장 멀리 튄 거리가 5% 이상(`CK.DRIFT_WOBBLE`).
- 숫자를 바꾸면 로직 파일의 상수, `content.json`의 글, `check.py`의 대조(`need`)를 같이 고친다. `check.py`가 어긋나면 실패한다.

## 설계 결정
- **권한은 단추를 눌렀을 때만.** 쪽을 여는 것만으로는 아무 권한도 묻지 않는다. 마이크·카메라가 켜진 동안 '끄기' 단추와 "어디에도 올라가지 않아요" 한 줄이 계속 보이고, 쪽을 떠나거나 탭이 가려지면 스스로 끈다.
- **켜면 늘어나는 칸은 단추를 누른 순간에 자리를 잡는다.** 권한 창에 답한 뒤에 칸이 늘어나면 아래 글이 늦게 밀린다(사용자 입력 뒤 0.5초가 지난 밀림은 CLS로 잡힌다). 그래서 마이크 쪽의 장치 고르기·녹음 칸, 웹캠 쪽의 단추 줄, 휴대폰 첫 화면의 카메라 창은 누르자마자 펴고, 실패해도 접지 않는다. 첫 화면 카메라의 '끄기'는 미리보기 안 왼쪽 아래 모서리에 얹었다(칸 높이가 그대로). 휴대폰 첫 화면의 카메라 창만 '끄기'를 누르면 다시 작아진다. `e2e.py`의 `late_shift`가 권한 창에 1.5초 뒤 답한 경우의 밀림을 잰다(허용 0.02, 거절 0.03 이하).
- **판정을 사람 말로 먼저.** "키 12개를 눌렀고 전부 잘 들어왔어요"가 먼저, 숫자·`code` 값은 그 아래와 '자세히 보기와 설정' 안에.
- 처음 보이는 자판 배열은 기기에 맞춘다(맥이면 맥 배열, 그 밖은 풀 104). `<head>`의 작은 스크립트가 첫 그림 전에 `html[data-kb]`·`[data-os]`를 정하고 CSS가 그 배열 그림 하나만 보여 준다(네 배열의 SVG가 모두 첫 HTML에 있다 → 화면 밀림 0). 고른 배열은 `ck.layout`에 남긴다. 첫 화면 점검판과 키보드 쪽이 같은 값을 쓰고, 둘 다 자판 위에 배열 고르기가 있다. 첫 화면의 자판 칸은 텐키리스 비율로 높이를 잡아 두어 배열을 바꿔도 아래 칸이 움직이지 않는다.
- 첫 화면 칸 머리는 좁다. 권한을 기다리는 동안의 글자는 한 줄에 드는 짧은 말(`t.ask_home`)을 쓴다.
- 마이크·카메라를 한 번 켰다 끄면 안내 줄은 "누르면 브라우저가 먼저 물어봐요"로 돌아가지 않고 "지금은 꺼져 있어요. 아무것도 올라가지 않았어요"가 된다(이미 허락을 받았으니 앞 문장은 틀린 말이 된다).
- 가이드 글의 숫자(채터링 표, 동시 입력 표, 16.67ms = 60Hz, -20 dBFS = 10분의 1)는 `tests/run.mjs`의 `guide` 묶음이 로직으로 다시 구해 글과 맞춰 본다. 글을 고치면 그 묶음도 같이 고친다.
- 한/영(`Lang1`·`HangulMode`)은 오른쪽 Alt 자리, 한자(`Lang2`·`HanjaMode`)는 오른쪽 Ctrl 자리에 켠다. 배열에 없는 키는 버리지 않고 '이 배열에 없는 키'로 보여 준다.
- **한쪽 신호만 오는 키**(제3자 평가 2026-10-10): 누름 없이 뗌만 온 키(운영체제가 누름을 가져간 키. 윈도우의 PrtSc가 그렇다고 알려져 있다)는 '한 번 눌렸다 떼어진 것'으로 켠다(눌려 있음·동시 입력 수에는 넣지 않는다). Caps Lock과 한/영·한자(`CK.isMomentary`)는 운영체제에 따라 누름만 오거나 뗌만 올 수 있어, 어느 쪽이 오든 한 번 눌린 것으로만 세고 눌린 채로 두지 않는다(맥 Caps Lock이 '걸렸을 수 있어요'로 나오던 일). 창을 벗어나거나 ⌘를 떼며 비운 키, 입력칸이 받은 키의 늦은 뗌은 새 누름으로 세지 않는다. 이 동작들을 화면 글에 쓸 때는 단정하지 않는다(공식 출처를 확인하지 못했다).
- **키 잡기**: 켜져 있으면 Tab·스페이스·F5까지 이 화면이 받는다(Ctrl·Command 조합은 빼고). Esc 두 번이면 돌려주고, 그 뒤에는 자판이나 '다시 키 받기'를 눌러야 다시 잡는다. 키보드 쪽은 첫 키에서 스스로 켜지되 Tab·조합 키, 링크·단추 위의 Enter·스페이스로는 켜지지 않는다(키보드만 쓰는 사람이 '본문으로 건너뛰기'와 메뉴를 쓸 수 있게). 안내 문장은 자판 위에 있고, 상태가 바뀌어도 줄 수가 같게 높이를 잡아 두었다. 첫 화면은 자판을 누르거나 '모든 키 받기'를 눌렀을 때만 켜지고(칸 머리에 "받는 중 · Esc 두 번이면 풀려요"), 그 전에는 화면을 굴리는 키만 막는다(초점이 링크에 있어도. 단추 위의 스페이스는 그 단추를 누른다).
- 배열 고르기에 초점이 남아 있어도 글자 키는 배열을 바꾸지 않고 테스트 키로 들어간다(화살표·Enter 등 고르는 데 쓰는 키만 그 칸이 받는다).
- 테스트 칸(`[data-mouse-area]`) 안에서는 오른쪽 단추 메뉴, 휠 누름 스크롤, 뒤로·앞으로 이동을 막는다. 첫 화면의 마우스 칸도 같다(칸 밖은 평소대로). 휠로 페이지가 굴러가지 않게 막는 것은 마우스 쪽만이다(첫 화면에서는 굴러가야 한다).
- **카메라는 낼 수 있는 가장 큰 크기를 요청한다**(`width: {ideal: 4096}, height: {ideal: 2160}`. `exact`는 못 맞추면 실패하니 쓰지 않는다). 화면에는 받은 값(트랙 설정)을 "브라우저가 받은 크기"라고 보여 주고, 되는 브라우저에서는 카메라가 밝힌 최대(`getCapabilities`)도 같이 보여 준다. 초당 장 수는 따로 요청하지 않는다(같이 요청하면 브라우저가 장 수를 맞추려고 더 작은 크기를 고를 수 있다). 조건 탓에 요청이 실패하면 조건 없이 한 번 더 요청한다.
- **마이크는 브라우저의 소리 다듬기(울림 제거·소음 억제·자동 음량)를 끄고 요청한다**(`ideal: false`). 실제 값은 트랙 설정에서 읽어, 켜져 있으면 "브라우저가 소리를 다듬고 있어요"라고 밝힌다. 마이크용 AudioContext는 켤 때 만들고 끌 때 닫는다. 스피커용은 소리가 없을 때 쉬게 한다.
- 게임패드: 표준 배치가 아니면 받은 단추 수·축 수 그대로 'Button N'·'Axis N'으로 그리고, 어느 축이 스틱인지 몰라 가만히 둔 값만 보여 준다(트리거가 축으로 오는 기기는 가만히 -1에 있다. 그것을 쏠림이라고 하면 틀린 말이다). 컨트롤러가 바뀌면 칸·이름·문구를 처음부터 다시 그린다.
- 이 탭에서 해 본 테스트는 세션 저장소 `ck.done`에 남겨 다른 쪽의 기기 띠에도 불이 켜진다(탭을 닫으면 사라짐). 실패(빨강)는 남기지 않는다.
- 불량화소 전체 화면: 색은 누르거나 키를 눌렀을 때만 바뀐다(스스로 넘기지 않는다). 전체 화면 칸 안에는 아무것도 없다. 전체 화면 API가 없으면 창을 가득 채운다.
- 주사율은 화면 120장만 재고 멈춘다. 움직이는 막대는 누르면 8초만 움직인다. 멈춰 있을 때 도는 타이머·반복 움직임은 없다.
- 광고 자리는 설명 글 아래(mid)와 맨 아래(bottom). 권한·녹음·전체 화면 단추에서 150px 넘게 떨어져 있고(`e2e.py`가 잰다), 첫 화면 점검판 안과 바로 옆에는 없다. 가이드 글의 mid 자리는 글 가운데 소제목 앞이다(맨 끝 '테스트 열기' 단추에서 150px 넘게). 소개·방침·가이드 목록·404에는 광고 코드가 없다.
- 다른 언어판 안내 띠는 화면 아래에 떠 있는 작은 띠다(`position: fixed`). 띠 밑에 누르는 것(단추·링크·탭·입력칸)이 오면 그동안 스스로 숨는다. 닫기 단추는 44px.
- 손가락으로 누르는 화면(`pointer: coarse` 또는 폭 640px 이하)에서는 누르는 곳의 높이를 44px 넘게 잡는다(글 속 링크는 그대로).
- 기기 띠는 900px 아래에서 두 줄 격자다(영어 이름이 길어 761~891px에서 한 줄에 안 들어갔다). 400px 아래에서는 켜진 불을 칸 모서리에 얹어 낱말이 가운데에서 끊기지 않게 한다.
- 연출 셋(요청문 전문은 프로젝트 문서): 루멘랩 표시등 줄(칸이 들어올 때 한 번), 불 지나가기(마지막 키를 눌렀을 때 한 방문에 한 번), 들려요 물결(마이크가 처음 소리를 잡았을 때 한 번). 기본 반응은 `--t` 하나. 동작 줄이기에서는 `html.anim`이 안 붙어 전부 꺼진다.
- 글꼴은 사이트가 직접 보내는 조각 하나(언어판마다)를 preload하고 `font-display: optional`로 쓴다. 제때 오면 첫 화면부터 쓰이고, 늦으면 그 쪽은 기기 글꼴로 보인다(이미 그린 글자를 바꾸지 않으니 줄이 다시 짜이지 않는다). 조각에 없는 글자(운영체제가 알려 준 장치 이름 등)는 기기 글꼴로 보인다.
- 화면 코드가 붙이는 상태 클래스(`is-…`)와 칸 모양 클래스의 이름을 겹치지 않는다. 자판 연출 클래스가 스피커 칸의 `.sweep` 모양 규칙을 물려받아 자판이 33px 밀렸던 일이 있다(지금은 `is-sweeping`과 `spk-sweep`. `check.py`가 본다).

## 주의할 점
- 기기 저장소 키는 `ck.layout`·`ck.chatter`·`ck.dblclick`·`ck.lang`(localStorage), `ck.done`(sessionStorage) 다섯 개뿐이다. 키를 더하면 방침(`content.json` `privacy`)과 `check.py`의 `KEYS`를 같이 고친다.
- `<head>`의 첫 그림 전 스크립트(맥 판별)와 `CK.defaultLayout`은 같은 규칙이어야 한다(`e2e.py`가 맥 흉내로 대조한다).
- 방침의 '방문 통계' 문단(Cloudflare Web Analytics)을 지우거나 "분석 도구를 쓰지 않는다"는 뜻의 문장을 넣지 않는다. Cloudflare가 실제 주소에서 통계 스크립트를 끼워 넣는다.
- 화면 확인에서 키·마우스를 흉내 낼 때는 사람처럼 사이를 둔다(바로 이어 누르면 30ms·50ms 기준에 걸려 '의심'이 뜬다). 간격을 정확히 만들 때는 CDP `Input.dispatchKeyEvent`·`dispatchMouseEvent`의 `timestamp`를 쓴다. 시각이 앞 이벤트보다 과거면 브라우저가 이동 이벤트를 넘기지 않는다.
- Playwright `evaluate`에 넘긴 글이 함수로 끝나면 그 함수를 불러 버린다(끝에 `; 0`).
- 화면 코드가 쓰는 문장(`T.이름`)은 `content.json`의 `t.en`·`t.ko` 둘 다에 있어야 한다(`check.py`가 본다. 빠지면 화면에 undefined가 뜬다).
- 3단계에 확인돼 쓴 사실(2026-10-10, `verified-check.md` 5~7번, 출처 링크는 화면에 있다): 맥에서 ⌘를 누른 동안 다른 키의 뗌이 오지 않는 일(파이어폭스 버그 1299553. 다른 브라우저도 그렇다는 말은 신고자의 댓글일 뿐이라 쓰지 않는다) → 키보드 쪽 FAQ. USB 기본(boot) 보고 형식은 조합 키 8개 + 일반 키 6개(USB-IF HID 1.11 부록 B·C. '모든 USB 키보드가 6키'라는 뜻이 아니고 '6KRO'라는 말은 규격에 없다) → 동시 입력 글. XInput.h에 들어 있는 데드존 값 7849·8689(마이크로소프트의 말은 '권장'이 아니라 'provided'. 약 24%·26.5%는 우리 계산) → 게임패드 쪽 설명.
- 확인해서 쓴 사실(2026-10-10, 출처 링크는 화면에 있다): W3C의 `code` 표에 한/영 = `Lang1`, 한자 = `Lang2`가 있고 둘 다 꼭 줘야 하는 값은 아니다. MDN 표에는 윈도우에서 브라우저에 따라 그 `code`가 빈 값인 경우가 적혀 있다(그래서 `resolveKey`는 `code`가 비면 `key`의 `HangulMode`·`HanjaMode`로 자리를 찾는다). 윈도우 한국어 입력기는 오른쪽 Alt로 한/영, 오른쪽 Ctrl로 한자를 바꿀 수 있다(Microsoft Learn). `Lang1`·`Lang2`는 일본어 맥 자판의 키이기도 하니 '한/영 전용'이라고 쓰지 않는다. getUserMedia 예외의 뜻은 MDN 설명을 따른다(`CK.classifyMediaError`). 권한 창을 그냥 두면 답이 끝내 안 올 수 있어 15초 뒤 다시 누르라고 알려 준다(`media.js` `asking`).
- 공식 출처를 확인하지 못한 사실(한/영 키가 정확히 `AltRight` + `HangulMode`로 온다는 것, 브라우저가 마우스 위치를 화면 한 장에 한 번만 알려 주는지, 단추를 누르기 전에는 게임패드가 안 보이는지, Fn 키, 윈도우의 PrtSc가 뗌만 준다는 것, 맥 Caps Lock이 켤 때 누름만·끌 때 뗌만 준다는 것, 파이어폭스·사파리가 막았을 때와 창을 닫았을 때 같은 오류 문장을 준다는 것, F11을 페이지가 막을 수 없다는 것)은 화면에 단정해서 쓰지 않는다("…일 수 있어요", 이 도구가 하는 일만). 확인되면 출처 링크와 함께 고치고 `articles.json`의 `banned`에서 그 문장을 뺀다.
- 작업 공간에서는 진짜 소리·좌우, 실기기(키보드·마우스·게임패드·카메라), 아이폰 사파리를 확인할 수 없다. 가짜 장치(크롬 실행 인자)와 가짜 게임패드로만 본다. 진짜 PrtSc·Caps Lock의 신호, 진짜 카메라가 주는 해상도는 실기기에서만 확인된다.
- 광고 코드가 있는 실제 주소를 자동으로 열 땐 `googlesyndication|doubleclick|adservice|fundingchoices` 요청을 정규식으로 막는다(가짜 노출 = 무효 트래픽).
