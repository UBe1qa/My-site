# boot-repair · 가죽결 수선소 (연습용 가상 공방)

웹 연출 연습용 내 사이트. lvlrehab.com의 연출 뼈대(영상 첫 화면, 고정 무대 클로즈업, 여백 넓은 좌글·우그림, 고정 진행 그림, 늘 떠 있는 신청 바)를 부츠 수선 주제로 옮겼다.
- 2판(2026-10-13): 제3자 미감 피드백 세 차례 반영(모양 규칙 아래).
- 3판(2026-10-13): 원본 머리줄 메뉴가 실제 페이지(신청 자격·회생솔루션랩·성공사례·출연 방송·대표변호사·상담 예약)라서, 같은 구조로 하위 페이지 6개를 만들었다. 처음 화면 내용은 그대로 두고 메뉴만 페이지로 잇는다.
가격·기간·사례·수선사 소개는 예시이고 신청은 접수되지 않는다(알림·접수 화면 예시만).
주소: https://boot-repair.mysitebox.workers.dev (noindex). 배포는 `.deploy-actions` → GitHub Actions. 없는 주소는 `404.html`.
결정·연출 요청문은 My-site-private `context/knowledge/4-내-사이트/boot-repair-사이트-구조.md`.

## 페이지 (원본 → 여기)
- `/` 처음 화면: 첫 화면(필름) → 고정 무대(story) → 큰 숫자 → 흰 판(1분 견적·사진 견적·수선 전후·수선 예시·맡기는 순서·질문·끝)
- `/check/` 맡길 수 있나요 ← 신청 자격: 채팅식 세 질문 → 01 밑창 짜임(단면 그림) 02 짜임별 되는 수선 표 03 맡기는 부츠 04 사진 세 장
- `/repairs/` 수선 종류 ← 회생솔루션랩: 가격표 카드 → 01 부위 탭(그림에 고칠 곳 칠함) 02 통창갈이 열흘 03 사진 견적 무료
- `/cases/` 수선 사례 ← 성공사례: 어두운 띠 + 작업 태그 세 장 → 01 거르기 + 사례 카드(누르면 작업 태그 창) 02 가까이 전후. 후기는 지어내지 않는다
- `/care/` 관리법 ← 출연 방송: 비스듬한 카드 깔린 어두운 첫 화면 → 01 거르기 + 관리 카드 02 맡길 신호
- `/maker/` 수선사 ← 대표변호사: 가운데 큰 한 줄 → 01 작업 원칙 02 보는 순서(줄이 스크롤 따라 참) 03 재료. 경력·수상은 지어내지 않는다
- `/apply/` 수선 맡기기 ← 상담 예약: 왼쪽 안내·이어지는 순서, 오른쪽 신청서. `?items=heel,welt`(수선 id만)로 미리 고름. 사진은 화면에서만 미리 보기, 아무 데도 보내지 않음

## 파일
- 같은 조각(머리 링크·머리줄·메뉴·꼬리말·신청 바)은 `_dev/build.py`에만 있다. 페이지의 `<!--@top--><!--/@top-->` 같은 표시 사이를 채운다. 조각을 고치면 `cd _dev && python3 build.py`
- 입력 칸에는 name을 두지 않는다(스크립트가 꺼진 채 보내져도 이름·번호가 주소창에 실리지 않게)
- 모양 규칙(2판): 바탕 흰색·#F5F6F8 번갈이, 글자 짙은 남색, 강조 주홍 `--accent` 하나, 갈색은 그림 안에만(그림 채도 0.65). 글꼴 Pretendard 하나, 명조는 견적서 종이만. 처음 화면은 모든 칸 왼쪽 시작선 = `--gutter`. 하위 페이지 글 폭은 원본처럼 1084px(`.pwrap`)
- 하위 페이지 부품: `.phero`(첫 화면) `.stage`(연회색 큰 판 + 흰 카드 `.mcard`) `.num`(01) `.psec__title` `.endcta`(제목·단추·다음 페이지 카드 둘) `.filters/.fchip`
- `data.js` 수선 항목(`REPAIRS`)·맡기는 순서(`STEPS`)·처음 화면 예시(`CASES`)·수선 종류 설명(`REPAIR_INFO`)·사례(`CASE_LIST`)·관리법(`CARE`). 항목은 여기만 고친다
- `common.js` 모든 페이지: 알림, 머리줄 숨김, 휴대폰 메뉴, 신청 바(`[data-hero]`가 지나가면 나오고 `[data-dock-hide]`가 보이면 숨음), 드러내기(`data-rv="묶음"`), 전후 비교, 숫자 세기. `window.BR`
- `app.js` 처음 화면만: 견적(점·칩·견적서·도장), 수선 예시 카드, 맡기는 순서
- `sub.js` 하위 페이지: 자가 확인, 부위 탭, 사례 거르기·창, 관리 카드, 순서 줄, 신청서. `body[data-page]`로 고른다
- `film.js` 첫 화면 캔버스 '바느질 필름'. `motion.js` GSAP 3.15 + ScrollTrigger(처음 화면만, `html.anim`일 때)
- `img/` 코드로 그린 그림을 WebP로 굽은 것. 원본은 `_dev/art/make_paint.py` → `_dev/render.py`
- `_dev/` 확인 도구(배포 안 됨): `check.py`(페이지마다 폭별 넘침·깨진 그림·오류·숨은 요소 + 메뉴·신청서), `look.py`, `interact.py`, `perf.py`

## 명령
- 같은 조각 채우기: `cd _dev && python3 build.py`
- 그림 다시 굽기: `cd _dev/art && python3 make_paint.py && cd .. && python3 render.py`
- 확인: `cd _dev && python3 check.py` (몇 분 걸림)
